## YoukuTV（Apple TV 客户端）—— tvOS 构建修复 + 播放方案重构

### 背景
GitHub Actions 云端构建失败：
```
YoukuTV/Sources/WebPlayerView.swift:2:8: error: no such module 'WebKit'
** BUILD FAILED ** (exit code 65)
```

### 根因（重要认知修正）
**tvOS 自 9.0 起完全移除了 WebKit 框架。**
Apple 官方文档原话：*"WebView and WebPage are not available on tvOS.
tvOS has no WKWebView at all."*

日志里 SDK 和 target 都是对的（`AppleTVOS18.2.sdk` / `arm64-apple-tvos16.0`），
所以不是配置问题。bridging header 也救不了（`#import <WebKit/WebKit.h>` 同样失败）。

**教训**：任何基于"内嵌浏览器抓取"的方案在 tvOS 上立项时就应该排除。
早期基于 WKWebView 的"桥接方案"（拦截 Resource Timing 抓 m3u8）在浏览器里
验证完全通过，但在 tvOS 上根本无法编译——浏览器验证 ≠ 目标平台可行。

### 新架构
```
搜索/详情 → YoukuWebClient（普通 HTTP，实测可用）
播放     → YoukuUpsClient（mtop md5 签名 + ups 接口）→ stream[].m3u8_url → AVPlayer
```

### ckey 校验机制实测结论（单变量对照实验）
| 实验 | 结果 | 结论 |
|---|---|---|
| 原样重放（重新签名） | stream=2 | sign 过期无影响 |
| 只改 biz_params.vid | stream=10 | **ckey 不绑定 vid** |
| 改 utid | stream=0 | **ckey 绑定 utid** |
| ckey 置空 | stream=0 | ckey 必需 |
| 2 天前生成的 ckey | stream=2 | **有效期 > 2 天** |
| 页面 defaultCkey（老版） | stream=0 | 老版形态失效 |
| headless 浏览器生成的 ckey | stream=0 | **headless 生成的无效，必须有头浏览器** |

核心结论：ckey 与 vid 解耦、只绑 utid、存活数天 → 适合内置到 App。

### ups 接口要点
```
GET https://un-acs.youku.com/h5/mtop.youku.play.ups.appinfo.get/1.1/
    appKey=24679788  type=jsonp  callback=mtopjsonp1
    sign = md5(token & t & appKey & data)
data = { steal_params, biz_params, ad_params }   # 三段都是 JSON 字符串
```
- ccode 实测 = `0502`（之前猜的 0532 全错）
- 响应是 JSONP 包装 `mtopjsonp1({...})`，需剥离后再解析
- 播放地址在 `data.data.stream[].m3u8_url`
- m3u8 URL 带查询参数，不能用 `endsWith(".m3u8")`

# 2026-10-29 下午至晚间：三个关键 bug 与架构重构

## 1. 三个功能性 bug（语法和类型检查都过，但功能完全不可用）

| Bug | 现象 | 根因 |
|---|---|---|
| 详情页「播放」无响应 | 提示"暂无可播放资源" | `VideoItem.videoId` 恒为 `""` |
| 剧集列表永远为空 | 显示"暂无剧集信息" | `loadEpisodes` 走 TV 端 mtop（需设备指纹，返回空） |
| 搜索结果内容串台 | 搜「庆余年」打开《知否知否》 | 搜索接口混入外站内容，其 showId 指向别的节目 |

修复：新增 `YoukuEpisodeClient`（解析 H5 播放页 SSR）+ 过滤 `isYouku == 1`。

## 2. showId 污染（26% 比例）

`43efbfbd51efbfbdefbf` 这类 showId 含 UTF-8 替换字符 `efbfbd`。
**关键坑**：`efbfbd` 本身是合法 hex，字符集校验拦不住，必须显式排除子串。

## 3. 重大架构突破：绕开优酷 HTML 风控

发现优酷对 HTML 页面访问有**阿里 x5 风控**（`window._config_.action == "captcha"`），
反复访问返回 1549 字符的验证码页，**连真实 Chrome 都被拦**（标题「请验证后继续」）。
**JSON 接口不受影响**。

破局：搜索接口本身就带 vid（`commonData.leftButtonDTO.action.value`，
形如 `https://v.youku.com/v_show/id_{vid}.html`，覆盖率 75~100%）。

于是播放链路彻底改成纯 JSON：
```
search.youku.com/api/search  → vid + badge + showId
un-acs.youku.com ups         → m3u8
AVPlayer
```
选集列表降级为可选补充（走 HTML，可能被风控），失败不影响播放。

**修正错误结论**：`episodeInfo.benefitType != 0` ≠ 会员。
实测 0 和 1 都能播，只有 5 锁定。改用服务端 `posterDTO.iconCorner.tagText`
（"VIP"/"付费"/"独播"/"预告"）作为权威标识。

## 4. 六个编译阻断 bug（真实编译才发现）

`swiftc -parse` + `-typecheck` 全过，但**真实编译**暴露 6 个必失败 bug：

1. `AVURLAssetHTTPHeaderFieldsKey` 在 Swift 中**不存在**（我凭 ObjC 记忆写的）
   → 正确是 `AVURLAssetHTTPUserAgentKey`（tvOS 16+）
2. `removeObserver(obs)` 签名不匹配 → Swift 里要用 `observation.invalidate()`
3. `URLSession.data(for:)` 返回 `(Data, URLResponse)` → **两处解构顺序反了**
4. `try?` 返回可选元组 → 不能直接解构（两处）
5. `YoukuUpsClient` 缺 `import CryptoKit`（用了 `Insecure.MD5`）
6. **`primeToken()` 没抓响应 cookie** → `_m_h5_tk` 永远为空 → 整个 ups 通道运行时失效

**教训**：语法检查 ≠ 类型检查 ≠ 真实编译，三者查出的问题集合完全不同。
必须真编译。
