## YoukuTV（Apple TV 客户端）—— tvOS 构建修复 + 播放方案重构

### 背景
GitHub Actions 云端构建失败：
```
YoukuTV/Sources/WebPlayerView.swift:2:8: error: no such module 'WebKit'
** BUILD FAILED ** (exit code 65)
```

### 根因（重要认知修正）
**tvOS 自 9.0 起完全移除了 WebKit 框架。**
Apple 官方文档原话：*"WebView and WebPage are not available on tvOS.
tvOS has no WKWebView at all."*

日志里 SDK 和 target 都是对的（`AppleTVOS18.2.sdk` / `arm64-apple-tvos16.0`），
所以不是配置问题。bridging header 也救不了（`#import <WebKit/WebKit.h>` 同样失败）。

**教训**：任何基于"内嵌浏览器抓取"的方案在 tvOS 上立项时就应该排除。
早期基于 WKWebView 的"桥接方案"（拦截 Resource Timing 抓 m3u8）在浏览器里
验证完全通过，但在 tvOS 上根本无法编译——浏览器验证 ≠ 目标平台可行。

### 新架构
```
搜索/详情 → YoukuWebClient（普通 HTTP，实测可用）
播放     → YoukuUpsClient（mtop md5 签名 + ups 接口）→ stream[].m3u8_url → AVPlayer
```

### ckey 校验机制实测结论（单变量对照实验）
| 实验 | 结果 | 结论 |
|---|---|---|
| 原样重放（重新签名） | stream=2 | sign 过期无影响 |
| 只改 biz_params.vid | stream=10 | **ckey 不绑定 vid** |
| 改 utid | stream=0 | **ckey 绑定 utid** |
| ckey 置空 | stream=0 | ckey 必需 |
| 2 天前生成的 ckey | stream=2 | **有效期 > 2 天** |
| 页面 defaultCkey（老版） | stream=0 | 老版形态失效 |
| headless 浏览器生成的 ckey | stream=0 | **headless 生成的无效，必须有头浏览器** |

核心结论：ckey 与 vid 解耦、只绑 utid、存活数天 → 适合内置到 App。

### ups 接口要点
```
GET https://un-acs.youku.com/h5/mtop.youku.play.ups.appinfo.get/1.1/
    appKey=24679788  type=jsonp  callback=mtopjsonp1
    sign = md5(token & t & appKey & data)
data = { steal_params, biz_params, ad_params }   # 三段都是 JSON 字符串
```
- ccode 实测 = `0502`（之前猜的 0532 全错）
- 响应是 JSONP 包装 `mtopjsonp1({...})`，需剥离后再解析
- 播放地址在 `data.data.stream[].m3u8_url`
- m3u8 URL 带查询参数，不能用 `endsWith(".m3u8")`

### 环境踩坑
- Git 推送偶发 `HTTP2 framing layer` / `CONNECT tunnel failed 502` → 加 `-c http.version=HTTP/1.1` 重试可过
- GitHub 免费账户 macOS runner 供给紧张，单个 runs-on 标签可能排队 15+ 分钟
  → 改成 `runs-on: [macos-15, macos-14]` 数组让 GitHub 自动挑有容量的
- `swiftc -parse` 只查语法，查不出类型错误；用 `-typecheck -sdk $(xcrun --show-sdk-path --sdk macosx)`
  可暴露大部分问题（macOS 平台差异错误需人工排除）
