# tvOS 27 侧载：菜单名变更与配对排查（2026-10-31）

## 用户问题
"没有在 appletv 上找到这些设置"（配对码 + 信任开发者两处都找不到）

## 根因（三处，全部是文档/流程问题，不是环境问题）

1. **菜单名错**：我写的是「远程 App 与设备」（英文直译），
   tvOS 27 实际叫 **「遥控器 App 与设备」**。
   依据：Apple 官方中文手册 + atvloadly 中文 README 交叉验证。
   → 教训：系统菜单必须查目标版本的中文官方手册，不能英文直译。

2. **信任选项安装前不存在**：「设置 › 通用 › 隐私与安全性 › App 安装」
   只有设备上存在待信任证书时才出现。装之前根本没这行菜单，
   所以把"信任"当成安装前的准备步骤是逻辑倒置。

3. **tvOS 26.4+ 换了 mDNS 服务名**：
   `_apple-pairable._tcp` → `_remotepairing-manual-pairing._tcp`
   老 Sideloadly(≤0.60) 认不出。解法：升级 ≥0.61，或两边忘记 WiFi 重连。

## 实测环境（全部通过）
- macOS 26.2 (25C56)
- Sideloadly **0.71.2**（≥0.61，无 mDNS 问题）
- Mac IP 192.168.101.133
- Apple TV: **192.168.101.112**，实例名 "Apple TV"
  （注意空格是 U+00A0！）
- 配对服务 `_remotepairing-manual-pairing._tcp` **广播正常**
- 局域网还有另外两个 AirPlay 接收端："客厅"、"客厅 (2)" → 选设备别选错
- IPA 238KB / arm64 / tvOS 16.0+ / UIDeviceFamily=[3] / 无 debug.dylib

## 新增工具
`tools/检查AppleTV配对.py` — 用 dns-sd 分层诊断：
- 第1层扫 `_airplay._tcp` + `_companion-link._tcp` → 电视在不在
- 第2层扫 `_remotepairing-manual-pairing._tcp` + `_apple-pairable._tcp`
  → 配对模式开没开（只有停在配对页才广播）

## 踩坑：dns-sd 输出里的 U+00A0
实例名 "Apple TV" 内部空格是 **U+00A0 不换行空格**，列分隔符却是普通空格。
- `re.split(r"\s+")` → 名字被拆成 Apple / TV
- `replace("\xa0"," ")` 再切 → 列分隔也乱了
- ✅ 只按普通空格切：`line.strip().split(" ")`，实例名里的 U+00A0 原样保留
- 比较时再归一化：`s.replace("\xa0"," ").lower()`

## 待办
用户下一步：Apple TV 停在「遥控器 App 与设备」页 → Sideloadly 选 Apple TV
→ 填 Apple ID → Start → 装完再去信任开发者。

# 五个缺陷的根因定位与修复收尾（2026-10-31 下午）

## 根因（每条都有实测证据，见 `逆向分析报告.md` 第 15 章）
1. **无 icon 和名称** — XcodeGen `sources` 没含资源目录 → 无 `Assets.car`。
   关键：`type` 必须是 `file`（生成 `folder.assetcatalog` 的 PBXFileReference），
   `folder`/`group` 都不会进 actool。
2. **不适配 2160P** — `LaunchImage.imageset` 只有 1920x1920 的 1x。
   tvOS 无 3840x2160 的 2x 启动图 → 系统判定只支持 1080p → 兼容模式缩到 1/4。
3. **无账号登录态** — 三个坑叠加：
   - `data.code` 是**字符串** `"3000"`，`as? Int` 静默失败 → 报「失败：成功」
   - `tokenInfo` 必须**严格 12 字段**（fastjson 未开 WriteMapNullValue，null 全省略）
   - `returnValue.data` 是**字符串**，凭据要**三重 parse**（data→loginServiceExt→youkuExt→content）
4. **视频无法播放** — ups 响应是 `data.data.stream` 三层，代码读的是 `data["stream"]`
5. **无法返回主页** — 自定义 route 在根视图 switch，不是真导航栈 → 改 `NavigationStack(path:)`

## CI/打包连踩的坑
- macOS 自带 `zip` 在追加场景产出损坏归档 → 改用 Python `zipfile`（`YoukuTV/tools/打包IPA.py`）
- 脚本在 `YoukuTV/` 下跑但 Payload 在 `build/` → 传 `build/Payload`
- IPA 条目路径不能带 `build/` 前缀，必须 `Payload/...`（用 `os.path.basename` + `relpath(p, payload)`）
- **`actions/download-artifact` 的 `merge-multiple: true` 让合并产物损坏**：
  各路 artifact 里文件同名 `YoukuTV-unsigned.ipa`，合并时互相覆盖 →
  字节差 53 万处但中央目录一致。修复：去掉 merge-multiple，
  finalize 里**逐个校验只发布通过的**。
- `CFBundlePrimaryIcon` 被 Xcode 扁平化成字符串，校验脚本要兼容字符串/字典两种

## 关键工具（都留在 tools/ 下）
- `tools/登录联调/` — macOS 命令行版扫码登录，**复用同一份 Swift 源码**
  （YoukuLoginClient.swift 只依赖 Foundation+CryptoKit，macOS 可编译）。
  价值：把「协议错」和「UI 错」分开。认证协议问题在这直接暴露。
- `tools/校验IPA.py` — IPA 结构校验（CRC/重复条目/前缀/关键文件/图标键/Mach-O架构）
- `tools/定向推送.py` — 按文件列表推送（`tools/推送GitHub.py` 全量比对版会超时）
- `tools/实测播放链路.py`、`tools/攻坚登录协议.py`

## 环境事实
- git 协议层不通（HTTP2 framing error / 代理 502）→ 一律用 GitHub Git Data API 推送
- Swift 短字符串（≤15字符）在二进制里找不到 → 小字符串优化内联，不是资源缺失
- 沙箱里 `&` 起的常驻进程会被回收 → 必须用 run_in_background
