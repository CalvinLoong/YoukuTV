# tvOS 27 侧载：菜单名变更与配对排查（2026-10-31）

## 用户问题
"没有在 appletv 上找到这些设置"（配对码 + 信任开发者两处都找不到）

## 根因（三处，全部是文档/流程问题，不是环境问题）

1. **菜单名错**：我写的是「远程 App 与设备」（英文直译），
   tvOS 27 实际叫 **「遥控器 App 与设备」**。
   依据：Apple 官方中文手册 + atvloadly 中文 README 交叉验证。
   → 教训：系统菜单必须查目标版本的中文官方手册，不能英文直译。

2. **信任选项安装前不存在**：「设置 › 通用 › 隐私与安全性 › App 安装」
   只有设备上存在待信任证书时才出现。装之前根本没这行菜单，
   所以把"信任"当成安装前的准备步骤是逻辑倒置。

3. **tvOS 26.4+ 换了 mDNS 服务名**：
   `_apple-pairable._tcp` → `_remotepairing-manual-pairing._tcp`
   老 Sideloadly(≤0.60) 认不出。解法：升级 ≥0.61，或两边忘记 WiFi 重连。

## 实测环境（全部通过）
- macOS 26.2 (25C56)
- Sideloadly **0.71.2**（≥0.61，无 mDNS 问题）
- Mac IP 192.168.101.133
- Apple TV: **192.168.101.112**，实例名 "Apple TV"
  （注意空格是 U+00A0！）
- 配对服务 `_remotepairing-manual-pairing._tcp` **广播正常**
- 局域网还有另外两个 AirPlay 接收端："客厅"、"客厅 (2)" → 选设备别选错
- IPA 238KB / arm64 / tvOS 16.0+ / UIDeviceFamily=[3] / 无 debug.dylib

## 新增工具
`tools/检查AppleTV配对.py` — 用 dns-sd 分层诊断：
- 第1层扫 `_airplay._tcp` + `_companion-link._tcp` → 电视在不在
- 第2层扫 `_remotepairing-manual-pairing._tcp` + `_apple-pairable._tcp`
  → 配对模式开没开（只有停在配对页才广播）

## 踩坑：dns-sd 输出里的 U+00A0
实例名 "Apple TV" 内部空格是 **U+00A0 不换行空格**，列分隔符却是普通空格。
- `re.split(r"\s+")` → 名字被拆成 Apple / TV
- `replace("\xa0"," ")` 再切 → 列分隔也乱了
- ✅ 只按普通空格切：`line.strip().split(" ")`，实例名里的 U+00A0 原样保留
- 比较时再归一化：`s.replace("\xa0"," ").lower()`
